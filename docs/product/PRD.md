# 皮肤病变智能识别与辅助分析平台 — 产品需求文档 (PRD)

- 文档版本：1.0.0
- 需求来源：《皮肤癌图像检测系统项目任务书 V1.0.0》（校企联合实习实践项目下达的项目要求）
- 交付形态：响应式 Web 应用（WebApp），前后端分离
- 项目性质：校企联合 AI 应用实习实践项目，由广州泰迪智能科技有限公司相关人员参与指导与实践；
  非商业产品、非生产系统，未在任何医疗机构上线

> **免责声明（贯穿全系统）**
> 本系统仅作为皮肤健康辅助自检工具，检测结果仅供参考，不能替代专业医生诊断。
> 模型置信度并不等同于真实临床患病概率。

---

## 1. 项目背景

皮肤癌是最常见的癌症类型之一，其中黑色素瘤恶性程度高、易转移，早期筛查对预后至关重要。
传统诊断依赖经验丰富的皮肤科医生阅读皮肤镜图像，而专业医生资源分布不均，限制了大规模早期筛查的开展。

近年来，基于深度残差网络的图像分类方法在皮肤病变识别任务上取得了明显进展（这是公开研究背景，
**不是本项目的实测结果**；本项目在独立外部数据上的实测准确率为 78.54%，见
`docs/ml/EXTERNAL_EVALUATION.md`）。结合 Web 应用"跨平台、免安装、易传播"的特点，
可以构建一个面向普通用户的辅助分析工具。

## 2. 项目目标

### 2.1 总体目标

开发一款基于深度残差网络的皮肤癌图像检测 Web 应用：用户通过浏览器上传皮肤病变图像，
系统自动完成图像预处理与模型推理，输出**良性 / 恶性倾向**、模型置信度与概率分布，
并提供健康建议与医疗免责声明，检测记录可在个人历史中查阅、对比与导出。

### 2.2 具体目标

| 编号 | 目标 | 验收方式 |
| --- | --- | --- |
| G1 | 图像上传：拖拽或点击选择，支持 jpg/png/webp/bmp，上传前预览 | 前端组件测试 + E2E |
| G2 | 图像预处理：归一化、缩放至 224×224、格式转换 | 单元测试断言 `shape == [3,224,224]` |
| G3 | 深度学习识别：良性 / 恶性二分类，训练阶段准确率目标 ≥ 90% | 留出内部测试集一次性评估报告 |
| G4 | 结果展示：可视化结果、置信度、健康建议、就医指导 | 结果页 + 组件测试 |
| G5 | 历史记录：保存、查看、图像对比、导出 | API 测试 + E2E |
| G6 | 用户管理：注册、登录、个人信息管理、数据安全 | 后端测试 + 安全测试 |

## 3. 用户与使用场景

| 角色 | 描述 | 主要诉求 |
| --- | --- | --- |
| 普通用户 | 发现皮肤异常、希望初步了解风险的普通人 | 快速上传、得到倾向性判断与就医建议、隐私安全 |
| 开发者 / 维护者 | 本项目的实现与迭代者 | 可复现的训练流程、可读的代码与文档 |
| 项目评审方 | 校企联合实习实践中的指导与验收角色 | 可运行的完整系统 + 真实指标 + 文档齐备 |

典型场景：

1. 用户发现手臂上有一颗痣形状发生变化，用手机拍下照片，在浏览器中上传，几秒内得到"恶性倾向 87%"的结果与"建议尽快就医"的提示，并可将该记录与三个月前的记录并排对比。
2. 用户回顾自己的历史检测记录，导出 CSV 交给医生参考。
3. 评审方使用外部提供的独立图片，运行一条命令得到全部预测与（若有标签）评估指标。

## 4. 功能需求

### 4.1 用户认证 (FR-A)

| ID | 需求 | 优先级 |
| --- | --- | --- |
| FR-A1 | 用户可使用邮箱 + 用户名 + 密码注册 | 必须 |
| FR-A2 | 邮箱、用户名唯一；重复注册返回 409 | 必须 |
| FR-A3 | 密码长度 ≥ 8 且至少包含两类字符；使用 Argon2id 哈希存储 | 必须 |
| FR-A4 | 用户可使用邮箱或用户名登录 | 必须 |
| FR-A5 | 登录失败返回统一错误，不区分"用户不存在/密码错误" | 必须 |
| FR-A6 | 登录连续失败达到阈值后限流 | 应该 |
| FR-A7 | 会话通过 HttpOnly + SameSite=Lax Cookie 维持，服务端只保存 token 哈希 | 必须 |
| FR-A8 | 支持退出登录；状态变更接口需要 CSRF 令牌 | 必须 |
| FR-A9 | 可查看与修改个人信息（昵称、用户名） | 必须 |
| FR-A10 | 可删除账号，连带删除全部检测记录与加密图片 | 应该 |

### 4.2 检测 (FR-D)

| ID | 需求 | 优先级 |
| --- | --- | --- |
| FR-D1 | 支持拖拽与点击两种方式上传图片 | 必须 |
| FR-D2 | 上传前本地预览，可更换、移除图片 | 必须 |
| FR-D3 | 前端校验类型与大小；后端必须重新校验（不信任前端） | 必须 |
| FR-D4 | 后端真实解码图片，拒绝伪装文件、损坏文件、超大图（防解压炸弹） | 必须 |
| FR-D5 | 统一预处理为 224×224 + ImageNet 标准化，与训练/评估完全一致 | 必须 |
| FR-D6 | 使用训练完成的 ResNet 模型推理，输出良性/恶性、置信度、两类概率、模型版本、检测时间 | 必须 |
| FR-D7 | 返回健康建议与医疗免责声明文案 | 必须 |
| FR-D8 | 检测过程有上传中/推理中/成功/失败状态，防止重复点击 | 必须 |
| FR-D9 | 支持 `Idempotency-Key`，客户端重试不产生重复记录 | 应该 |
| FR-D10 | 模型不可用返回 503，推理异常返回 500，均不泄露内部细节 | 必须 |

### 4.3 历史记录 (FR-H)

| ID | 需求 | 优先级 |
| --- | --- | --- |
| FR-H1 | 检测结果保存到个人历史（真实数据库，非 localStorage） | 必须 |
| FR-H2 | 历史列表支持分页与按结果筛选 | 必须 |
| FR-H3 | 可查看历史详情，包含当时的图片与结果 | 必须 |
| FR-H4 | 用户只能访问自己的记录；越权返回 404（IDOR 防护） | 必须 |
| FR-H5 | 可选择两条记录并排对比（图片、预测、置信度、时间） | 必须 |
| FR-H6 | 支持删除单条记录（同时删除加密图片） | 必须 |
| FR-H7 | 支持导出 CSV，包含时间/结果/置信度/两类概率/模型版本 | 必须 |
| FR-H8 | CSV 中不得包含原始图片数据 | 必须 |

### 4.4 图像隐私 (FR-P)

| ID | 需求 | 优先级 |
| --- | --- | --- |
| FR-P1 | 限制上传大小（默认 10 MB）与像素数 | 必须 |
| FR-P2 | 不信任 MIME 头，必须真实解码 | 必须 |
| FR-P3 | 服务端生成存储文件名，防止路径穿越 | 必须 |
| FR-P4 | 去除 EXIF 等元数据后存储 | 必须 |
| FR-P5 | 图片在服务端加密落盘（Fernet/AES + HMAC），密钥来自环境变量 | 必须 |
| FR-P6 | 读取历史图片必须先做授权校验，再解密返回 | 必须 |
| FR-P7 | 不公开任何静态图片目录 | 必须 |
| FR-P8 | 日志不得输出原始图片/base64/密钥/密码 | 必须 |

### 4.5 界面与非功能需求 (FR-U / NFR)

| ID | 需求 | 优先级 |
| --- | --- | --- |
| FR-U1 | 页面：首页、注册、登录、检测、结果、历史、历史详情、对比、个人中心、关于/免责声明 | 必须 |
| FR-U2 | 响应式：PC 双栏、移动端单栏，表格转卡片，按钮可触控 | 必须 |
| FR-U3 | 无障碍：语义化 HTML、表单 label、键盘可达、焦点可见、不依赖颜色传达状态 | 必须 |
| FR-U4 | 状态：loading skeleton、空状态、错误状态、二次确认对话框 | 必须 |
| NFR-1 | 浏览器：Chrome / Edge / Firefox / Safari 最近两个版本 | 必须 |
| NFR-2 | 单张图片推理延迟 < 1 s（CPU 或 GPU，需实测记录） | 应该 |
| NFR-3 | 并发推理有上限，防止 CPU 饱和 / GPU OOM | 必须 |
| NFR-4 | 数据/文件写入失败可回滚，不产生孤儿文件 | 必须 |
| NFR-5 | 提供 Docker Compose 一键启动与后端健康检查 | 应该 |
| NFR-6 | 所有错误响应遵循统一错误契约 | 必须 |

## 6. 验收条件

### 6.1 模型验收

- 数据划分科学、无泄漏（train/val/test 三重交集为空，含重复图检测）；
- 报告 Accuracy、Precision、Recall(Sensitivity)、Specificity、F1、ROC-AUC、混淆矩阵；
- 明确标注 `TARGET >=90%: ACHIEVED / NOT ACHIEVED`，不得修饰；
- 所有指标来自真实评估，不得硬编码。

### 6.2 系统验收

- 注册 → 登录 → 上传 → 预览 → 检测 → 结果 → 历史 → 详情 → 对比 → 导出 → 退出 全流程可用；
- 用户 A 无法访问用户 B 的任何记录；
- 图片以密文形式存在于磁盘；
- 所有测试命令可复现（详见 `docs/testing/TEST_REPORT.md`）。

### 6.3 交付物验收

- 代码、模型文件、训练代码、评估报告；
- 文档：PRD / 架构 / UI-UX / 数据库 / API / 模型报告 / 测试报告 / 部署 / 运维 / 项目报告；
- 提示词文件与可复用 Skill；
- 独立外部评测的一键入口（评测已于 2026-09-10 完成，结果见 `docs/ml/EXTERNAL_EVALUATION.md`）。
